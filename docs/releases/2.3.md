# Dekan 2.3

This update merges the maintainer-provided public 1.16 source changes into Dekan 2.2 and replaces both supplied Windows x64 bridge components. The source workspace is stamped as 2.3.0; user-facing version strings display 2.3.

## Changes

- Updated the locked `url` dependency to its fixed 2.5.9 release after the dependency gate reported RUSTSEC-2026-0592.
- Updated skin generation, loading-name records, TFT generation, form handling, audio banks, and chroma preview caching.
- Added repair actions, custom-mod repair feedback, and per-skin match statistics.
- Updated client lockfile discovery and platform discovery of installed Mod Manager executables, including explicit `DEKAN_LTK_MANAGER` and `LTK_MANAGER_EXE` overrides.
- Added the upstream party identity protocol updates while retaining Dekan's relay configuration and DNS recovery implementation.
- Retained Dekan's standalone skin picker, three saved themes, logos and icons. New repair and statistics cards use the active theme palette.
- Retained Turkish and English only, with Turkish translations for every new control and feedback message.
- Both the GitHub project button and the star gate target `chrisssst/Dekan`.

## Native bridge

The maintainer-supplied launcher and DLL replace the old vendor payloads byte for byte. The public filenames are `dekan_launcher.exe` and `dekan_bridge.dll`. Packaging also creates a hidden, identical `bullet_bridge.dll` compatibility copy required by the launcher. The internal `BulletBridge` handshake and per-session authentication profile are unchanged. The updated SHA-256 pins and provenance are recorded in `vendor/native/manifest.json`.

Native in-client mode is opt-in in Options. The client interface was recovered statically from the supplied 1.16 installer; its CDP coordination is implemented in Dekan. The menu, logo, repository/star links and Discord invite use Dekan assets and destinations. Client commands use the same validated selection, mod and party dispatch as the standalone picker. The supplied verified helper installs a LeagueClientUx debugger shim with an explicit UAC prompt. Interface restart is deferred until the client is idle or in a lobby; no restart occurs in champion select, loading, a match or reconnect. Disabling native mode or exiting removes the script and requests removal of this launcher’s shim. If removal is declined, disable the mode on the next start to retry. Another application’s debugger registration is retained. The existing pre-game arming behavior is unchanged.

The themed standalone picker stays available until CDP initialization and the skin carousel are both confirmed. Native-mode source reconstruction and mock tests do not establish compatibility with a particular live League client version.

## Preservation

`2.3-preservation.json` records checks for the original Rich Presence implementation, release/OAuth configuration, webhook workflow, relay configuration, logos, license and theme palette. These values were compared against the uploaded Dekan 2.2 source without copying their values into logs.

## Verification

Formatting, parser/party/skin-generation tests and repository policy sweeps are checked locally where supported. The full Windows build, UI tests, packaging, installer and dependency gates run through the existing GitHub Actions workflows. A successful CI run is not a real-match result. No real-match test has been performed in this environment, and this update does not promote a release to latest.
